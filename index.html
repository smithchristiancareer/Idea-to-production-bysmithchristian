Before You Begin: Installation

Configure your tools before diving into Claude Code.

To run these custom slash commands (/spec, /qa, /ship), you need to have both frameworks installed. Check out their step-by-step installation guides on GitHub:

1. Superpowers CLI ↗

Installs custom workflow shortcut templates inside your workspace environment. Check GitHub's "Installation" section.

2. Garry Tan's gstack ↗

Garry Tan's high-performance structural stack template used as your project root structure.

🚀

Once installed, simply run claude in your terminal within your initialized project repository, then head straight down to customize your playbook options!

Phase 1 of 5

Have the Idea

Turn a rough idea into something specific enough to actually build. No actual code is written here.

Talk through your idea before building anything

Brainstorm

Claude acts as your collaborative thinking partner. Let it iron out the rough edges before you commit.

COPY & PASTE TO CLAUDE 
/superpowers:brainstorming
I want to build a feature: [My Idea]. Help me think through scope, edge cases, and whether this should be opt-in or default.
Then:

Claude asks you simple clarifying questions. Answer them plainly to narrow a vague idea into a specific, buildable roadmap.

Create an isolated folder for your project

Workspace

Never mix features. Keep things separated so Claude has high context without noise.

COPY & PASTE TO CLAUDE 
/new-usecase [Slug Name]
Then:

A fresh workspace structure is generated, keeping code files isolated from other features.

Lock down a Product Specification

Spec

Draft a single source of truth describing exactly what the feature does, key requirements, and limitations.

COPY & PASTE TO CLAUDE 
/spec
Feature Name: [Slug Name]
Description: [My Idea]
Specific guidelines: Use clear modern styles, responsive layout, opt-in by default, and handle unexpected failures gracefully.
Then:

Claude produces a markdown specification file. This acts as your guardrail for development.

Write an implementation plan for the [Slug Name] spec.

Run a double-check auto plan validation

Validate that the plan has no architectural flaws, logic traps, or potential timezone issues before building.

CRITICAL CHECKPOINT: Approve Design First

Stop Sign

Do not let Claude touch any background logic code until you are absolutely satisfied with the look and feel. Adjusting HTML/CSS is fast; adjusting deep backend systems is slow.

COPY & PASTE TO CLAUDE 
Approved design! Proceed to build the structural layouts first, followed by functional logic as outlined in our step-by-step plan.
Phase 4 of 5

Build It

Develop incrementally with structural guardrails and strict quality assertions.

Build Segmented Components

TDD

Focus strictly on one task item at a time. Do not write the entire codebase in one single prompt.

COPY & PASTE TO CLAUDE 
/superpowers:test-driven-development

Apply Systematic Debugging on Errors

Debugging

If an interaction fails or an output breaks, run a precise analysis. Don't let Claude wild-guess the solution.

COPY & PASTE TO CLAUDE 
/superpowers:systematic-debugging
The UI changes are not saving as expected when refreshed. Run a systemic root-cause investigation.

Verify end-to-end functionality

Verify

Ensure all functions work sequentially, states resolve perfectly, and errors recover natively.

COPY & PASTE TO CLAUDE 
/superpowers:verification-before-completion
Confirm all layout controls and interactive inputs work flawlessly together end to end.

Trigger comprehensive Quality Assurance

QA

COPY & PASTE TO CLAUDE 
/qa
Test all interactive states and responsive layouts in our current workspace.
